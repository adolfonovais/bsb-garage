WhatsApp: envia OS, orcamento e NF como PDF anexado (nao mais link)

- src/lib/pdf.ts gera o PDF chamando a propria pagina de impressao (DocumentoImprimivel/DocumentoNfseImprimivel) num Chromium headless (@sparticuz/chromium-min + puppeteer-core) -- mesmo resultado visual do botao "Imprimir / PDF", so que gerado no servidor. So funciona no ambiente da Vercel (binario Linux).
- Paginas /imprimir/os, /imprimir/orcamento e /imprimir/nfse passam a aceitar um token interno de curta duracao (5 min) como alternativa a sessao de login -- usado so pelo proprio Chromium headless, nunca exposto ao cliente final (src/lib/doc-acesso.ts, novo tipo de token "pdf-interno" em tokens.ts). proxy.ts libera /imprimir/* da checagem de sessao, ja que a pagina passa a se autorizar sozinha.
- whatsapp.ts: upload do PDF pra Meta (media id) + envio de template com cabecalho de documento; mantem o envio de texto (aviso de OS concluida) e adiciona envio de texto livre (base pra respostas manuais da caixa de entrada, feature futura)
- Novas Server Actions: enviarOsPorWhatsApp, enviarNfPorWhatsApp (ordens-servico/actions.ts) e enviarOrcamentoPorWhatsApp (orcamentos/actions.ts), compartilhando o fluxo em src/lib/envio-documentos-whatsapp.ts
- Botao "Enviar OS" / "Enviar NF" / "Enviar orcamento" nas telas de OS e orcamento, visivel so quando a organizacao tem WhatsApp configurado (Organizacao.whatsappPhoneId)
- Schema: Organizacao.whatsappPhoneId (Phone Number ID por organizacao, roteia o futuro webhook) + model MensagemWhatsApp (historico, base da caixa de entrada que ainda sera construida) -- migracao 20261001120000_whatsapp_caixa_entrada
- Templates Meta esperados (cabecalho tipo Documento, corpo com {{1}} nome e {{2}} numero): envio_os, envio_orcamento, envio_nf -- enviados pelo usuario para analise
